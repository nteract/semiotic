# Public API proposals

Use [the template](TEMPLATE.md) to record proposals whose public API or
compatibility tradeoffs need discussion. A feature issue and a small compatible
PR can be sufficient; this directory does not make an RFC mandatory for every
change. Use a numbered descriptive filename and link the demand source and
implementation PR when available. Do not copy private proposals here without
authorization.

Start with status **Proposed**. Record discussion and alternatives, then update
the status to **Accepted**, **Rejected**, **Withdrawn**, or **Superseded** with a
linked decision and rationale. Acceptance records a design decision; shipping
still requires implementation and evidence. There is no mandatory cooling
period or consumer approval requirement established by this process.

Identify observable completion criteria and, when replacing a workaround or
API, the evidence and compatibility plan needed before removing it. Summarize
consumer context publicly without requiring private repository access.
